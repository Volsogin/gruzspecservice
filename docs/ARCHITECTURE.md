# Архитектура

## Слои

```
api/v1/        тонкие роутеры: разбор запроса → вызов сервиса → ответ (Pydantic-схемы = контракт)
services/      сценарии: приём заявок, статусы, заказ по ссылке, чат, отзывы, калькулятор, outbox, бот
domain/        чистые правила без FastAPI/БД: схемы форм, LeadValidator, статусы и переходы,
               калькулятор, геометрия зоны, телефон, ИНН, режим работы, темы чата
integrations/  внешний мир за интерфейсами: LLMProvider (OpenRouter), Notifier (SMTP/файл, Telegram, Max),
               Storage (локальный диск), Geocoder (2ГИС), ReviewSource (JSON/CSV)
db/            модели SQLAlchemy, сессии, миграции Alembic
container.py   composition root: собирает всё один раз; тесты собирают его же с фейками
admin.py       SQLAdmin (готовая библиотека), main.py — фабрика приложения, middleware, жизненный цикл
```

Зависимости направлены внутрь: роутеры → сервисы → домен; интеграции подставляются через контейнер.
Доменные функции тестируются без БД и HTTP.

## Ключевые потоки

### Заявка
```
POST /leads ─► rate limit (IP) ─► LeadValidator (схема типа: honeypot, поля, телефон → +7XXXXXXXXXX,
               ИНН, VIN, geo, условные поля, согласие) ─► form_token ─► Idempotency-Key ─► rate limit (телефон)
            ─► ссылки (estimate_id, service_slug) ─► фото: magic bytes → декодирование → поворот по EXIF →
               перекодирование без метаданных (EXIF/GPS/XMP) → WebP-превью → Storage
            ─► ОДНА транзакция: lead + history(new) + client_channels(email) + idempotency + outbox
            ─► 201 (номер, public_token, ссылка, статус) ─► kick воркера
outbox-воркер ─► e-mail оператору, Telegram оператору (карточка + кнопки), письмо клиенту
```
Ошибка SMTP/Telegram не влияет на ответ: строка outbox получает `attempts+1`, экспоненциальный backoff
(10 с … 1 ч), после `OUTBOX_MAX_ATTEMPTS` — `dead` (видно в админке «Очередь уведомлений» и `/admin/outbox`).
Захват строк — короткая «аренда» (`processing` + дедлайн, `FOR UPDATE SKIP LOCKED` на Postgres), отправка — вне
транзакции, поэтому медленный SMTP не держит блокировки; упавший воркер — аренда истечёт, строку подхватят.

### Смена статуса
Единственная точка — `services/lead_status.change_status()`; её вызывают админка (действия), Telegram-кнопки и
`POST /admin/leads/{id}/status`. Проверка перехода (`new → accepted → on_the_way* → in_progress → completed`,
`* только onsite/tow`, `cancelled` из любого незавершённого) → история (кто, когда, комментарий) → outbox:
клиенту на e-mail и во все привязанные Telegram-чаты, обновление карточки в чате операторов.

### Telegram
- Операторы: карточка заявки в чат `OPERATOR_TG_CHAT_ID` с inline-кнопками допустимых переходов
  (`callback_data = st:<lead_id>:<status>`). Нажатия принимаются **только из чата операторов**.
- Клиент: бот не может написать первым по телефону/@username (так устроен Bot API). Поэтому кнопка
  «Получать статус в Telegram» = deep-link `https://t.me/<bot>?start=<public_token>`; `/start <token>`
  привязывает `chat_id` к заявке (`client_channels`). Поле «Telegram @username» в форме хранится **только для
  операторов** — чтобы написать клиенту вручную.
- Long polling для демо (не нужен публичный URL) или webhook (`TELEGRAM_MODE=webhook`, секрет в заголовке).

### Чат-ассистент
Порядок обработки сообщения (`services/chat/service.py`):
1. ждём телефон после запроса оператора → нашли номер → заявка `chat_handoff` с расшифровкой диалога;
2. диалог у живого оператора → сообщение пересылается в чат операторов (уровень B);
3. пользователь явно просит человека (регулярка) или соглашается на предложение → передача, **без LLM и уговоров**;
4. LLM (OpenRouter, tool calling, SSE-стрим) — если есть ключ и не исчерпан бюджет;
5. иначе FAQ-режим: правила + база знаний из БД (услуги, контакты, зона, гарантия), расчёт цены по «марка + работа».

Защита: LLM может вызвать `request_operator` только если серверная проверка подтверждает просьбу пользователя
(иначе tool возвращает `not_requested`); цены — только через `calculate_price` (системный промпт + данные
калькулятора); аргументы tools валидируются как пользовательский ввод; системный промпт запрещает менять правила.
Бюджет: `LLM_MAX_TOKENS`, длина сообщения, лимит сообщений в сессии, суточные лимиты запросов и токенов
(таблица `llm_usage`), rate limit по IP. Сбой/таймаут OpenRouter → событие `reset` и FAQ-ответ — чат не падает.
Уровень B (живой чат): оператор отвечает reply'ем на пересланное сообщение (или на карточку заявки из чата) →
ответ сохраняется и доставляется на сайт по SSE (`/chat/sessions/{id}/events`). Нет ответа
`CHAT_OPERATOR_WAIT_MINUTES` → возврат к боту, заявка уже создана (уровень A).

### Первый экран
`GET /bootstrap` собирает всё одним запросом, кэшируется в памяти на `BOOTSTRAP_CACHE_SECONDS`, хранится
сразу в трёх вариантах (raw / gzip / brotli), `ETag` по содержимому → `304`. Остальные ответы — GZip-middleware
(кроме SSE). Медиа — имена с хэшем, `Cache-Control: immutable` на год.

## Данные
`leads` (uuid, читаемый `number` GS-1001 из таблицы-счётчика, `public_token` 192 бита, тип, поля формы в
колонках + `details` JSON, точка/адрес/зона, `estimate_id`, `source`, статус, согласие: факт/время/версия,
`ip_hash` (HMAC, не сырой IP), user-agent), `lead_attachments`, `lead_status_history`, `client_channels`,
`outbox`, `idempotency_keys`, `estimates`, справочники цен, `services`, `settings` (key/value JSON),
`reviews`, `cases` + `case_photos`, `chat_sessions` + `chat_messages`, `llm_usage`. Время — UTC
(`UTCDateTime` гарантирует tz-aware и на SQLite); режим работы считается в `Europe/Saratov`.

## Безопасность
CORS из env; лимит тела (Content-Length и потоковый счётчик) → 413; лимиты multipart; security-заголовки
(строгий CSP на `/api` и `/media`); единый формат ошибок; маскирование телефонов/e-mail/токенов в логах, токены
заказов вырезаны из access-лога; admin-токен — `hmac.compare_digest`; `GET /orders/{token}` — одинаковый 404 для
«нет»/«неверный формат»/«чужой», rate limit, `noindex`, `no-store`; фото проверяются по содержимому, имена —
uuid+хэш, ключи хранилища проверяются против обхода путей; защита от decompression bomb (`MAX_IMAGE_PIXELS`).

## ПДн (152-ФЗ) — что сделано и что делали бы в проде
Сделано: обязательное согласие с сохранением факта, времени и версии текста (`legal.consent_version`), минимум
данных, IP хранится только как HMAC, EXIF/GPS вырезаются из фото, телефоны маскируются в логах и на странице заказа.
В проде: срок хранения заявок (например, 3 года) и фото (1 год) с фоновой очисткой; процедура отзыва согласия и
удаления данных по запросу (удаление лида каскадно удаляет вложения, историю и каналы; файлы — из Storage);
уведомление Роскомнадзора об обработке; хранение БД на территории РФ; журнал доступа операторов; шифрование бэкапов.

## Допущения
- Цифры статистики, цены калькулятора, отзывы и кейсы — **демонстрационные** (`is_demo`), в справочнике цифры
  противоречат друг другу; выбраны единые условные значения.
- Координаты СТО — плейсхолдер (центр Саратова) до запуска `make geocode-sto` с ключом.
- Зона «30 минут» — круг `avg_speed_kmh × eta_minutes` = 15 км (или явный `radius_km`); «по области» —
  упрощённый многоугольник Саратовской области (`dispatch.region_polygon`, помечен как приблизительный).
- Номера заявок `GS-1001…`; счётчик — строка в `counters` (UPDATE … RETURNING сериализует конкурентов).
- `form_token` (подписанная метка времени) по умолчанию **не обязателен** (`FORM_TOKEN_REQUIRED=false`), чтобы
  curl-примеры и чат работали; если передан — проверяется всегда. На проде включить.
- Rate limiter — в памяти процесса (одна реплика API). Для нескольких реплик — Redis за тем же интерфейсом.
  Telegram polling и outbox-воркер тоже рассчитаны на один процесс API (`RUN_BACKGROUND_TASKS=false` на остальных).
- Создание заявки из чата (tool `create_lead`) — только `callback`/`repair`/`parts`; для выезда и эвакуатора
  ассистент открывает форму с картой (`action: open_form`), потому что нужна точка.
- Согласие в чате передаётся фронтом флагом `consent` (при создании сессии или вместе с сообщением с телефоном).
- HEIC принимается и конвертируется в JPEG (браузеры HEIC не показывают).
- Модель по умолчанию — `google/gemini-2.5-flash-lite` ($0.10/$0.40 за 1M токенов, поддерживает tools, хороший
  русский), резерв — `openai/gpt-4.1-nano` через параметр `models` OpenRouter. При бюджете ~$2 и лимитах по
  умолчанию это тысячи диалогов.
- Демо-фото кейсов генерируются Pillow при seed (чужие изображения не используются).
